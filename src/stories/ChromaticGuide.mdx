## 📦 Configuration

### Prérequis

Le projet est déjà configuré avec:
- ✅ Storybook 9.x installé
- ✅ Package `chromatic` installé (`^13.3.3`)
- ✅ Fichier `chromatic.config.json` présent

### Étape 1: Configuration du token

#### Option A: Variable d'environnement locale

Créez un fichier `.env.local` à la racine du projet:

```bash
CHROMATIC_PROJECT_TOKEN=your_project_token_here
```

#### Option B: GitHub Actions (recommandé)

Ajoutez le token dans les secrets GitHub:
1. Allez dans **Settings** → **Secrets and variables** → **Actions**
2. Créez un nouveau secret: `CHROMATIC_PROJECT_TOKEN`
3. Collez votre token Chromatic

### Étape 2: Obtenir votre token

1. Connectez-vous sur [chromatic.com](https://www.chromatic.com/)
2. Créez un nouveau projet ou sélectionnez un projet existant
3. Copiez le **Project Token** depuis les paramètres

### Étape 3: Mise à jour du Project ID

Éditez `chromatic.config.json` et remplacez le placeholder:

```json
{
  "projectId": "VOTRE_PROJECT_ID_ICI",
  "buildScriptName": "build-storybook"
}
```

Le Project ID se trouve dans l'URL de votre projet Chromatic: 
`https://www.chromatic.com/builds?appId=YOUR_PROJECT_ID`

## 🚀 Commandes disponibles

### Démarrer Storybook en local

```bash
npm run storybook
```

Ouvre Storybook sur `http://localhost:6006`

### Build Storybook pour production

```bash
npm run build-storybook
```

Génère les fichiers statiques dans `storybook-static/`

### Lancer les tests Chromatic

```bash
npm run chromatic
```

**Ce que fait cette commande:**
- Build Storybook
- Upload les stories vers Chromatic
- Capture des screenshots de tous les composants
- Compare avec le baseline précédent
- Génère un rapport de différences

## 📸 Workflow de test visuel

### 1. Développement local

Lors du développement d'un nouveau composant:

```bash
# 1. Créer la story
# src/stories/components/MyComponent.stories.tsx

# 2. Vérifier visuellement dans Storybook
npm run storybook

# 3. Tester les variants et le dark mode
# Utilisez la toolbar Storybook pour basculer le thème
```

### 2. Tests avant commit

Avant de committer vos changements:

```bash
# Build et vérifier qu'il n'y a pas d'erreurs
npm run build-storybook

# Lancer les tests visuels (optionnel en local)
npm run chromatic
```

### 3. Review de Pull Request

Chromatic commentera automatiquement votre PR avec:
- 🟢 **Passed**: Aucun changement visuel
- 🟡 **Changed**: Changements visuels détectés → Review requise
- 🔴 **Failed**: Build Storybook échoué

## 🎨 Best Practices

### 1. Stories exhaustives

Créez des stories pour tous les états importants:

```tsx
export const AllStates: Story = {
  render: () => (
    <div className="space-y-4">
      <Button>Default</Button>
      <Button disabled>Disabled</Button>
      <Button variant="destructive">Destructive</Button>
      {/* ... tous les états */}
    </div>
  ),
};
```

### 2. Test du Dark Mode

Chromatic capture automatiquement les deux thèmes si vous utilisez le decorator dans `.storybook/preview.tsx`:

```tsx
decorators: [
  (Story, context) => {
    const theme = context.globals.theme || 'light';
    return (
      <div className={`${theme} bg-background text-foreground`}>
        <Story />
      </div>
    );
  },
],
```

### 3. Tests de responsive

Configurez les viewports dans `chromatic.config.json`:

```json
{
  "projectId": "...",
  "viewports": [
    320,  // Mobile
    768,  // Tablet
    1280  // Desktop
  ]
}
```

### 4. Ignorer les animations

Pour des tests plus stables, désactivez les animations:

```tsx
export const MyStory: Story = {
  parameters: {
    chromatic: { 
      delay: 300,  // Attendre 300ms avant la capture
      pauseAnimationAtEnd: true 
    },
  },
};
```

## 🔧 Configuration avancée

### Ignorer certaines stories

Si une story contient des éléments non-déterministes (dates actuelles, données aléatoires):

```tsx
export const WithCurrentDate: Story = {
  parameters: {
    chromatic: { disableSnapshot: true },
  },
};
```

### Tests de diffing sélectif

Pour ignorer certaines régions de l'UI:

```tsx
<div data-chromatic="ignore">
  {/* Contenu ignoré par Chromatic */}
  <CurrentTime />
</div>
```

### Optimiser les crédits Chromatic

```json
{
  "projectId": "...",
  "onlyChanged": true,  // Tester uniquement les stories modifiées
  "exitZeroOnChanges": false,  // Échouer si changements détectés
  "exitOnceUploaded": true  // Ne pas attendre les résultats
}
```

## 🤖 Intégration CI/CD

### GitHub Actions (recommandé)

Créez `.github/workflows/chromatic.yml`:

```yaml
name: Chromatic Visual Tests

on:
  push:
    branches: [main, develop]
  pull_request:

jobs:
  chromatic:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0  # Nécessaire pour Chromatic

      - uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'

      - name: Install dependencies
        run: npm ci

      - name: Run Chromatic
        uses: chromaui/action@latest
        with:
          projectToken: ${{ secrets.CHROMATIC_PROJECT_TOKEN }}
          buildScriptName: build-storybook
          onlyChanged: true  # Optimisation
          exitZeroOnChanges: true
```

### Workflow recommandé

1. **Branches de feature**: Tests sur chaque push
2. **Pull Requests**: Review visuelle obligatoire
3. **Main/Develop**: Mise à jour du baseline automatique

## 🆘 Troubleshooting

### Problème: Build Storybook échoue

```bash
# Tester le build localement
npm run build-storybook

# Vérifier les erreurs TypeScript
npm run type-check
```

### Problème: Trop de changements détectés

```bash
# Réinitialiser le baseline
npm run chromatic -- --auto-accept-changes
```

### Problème: Token invalide

Vérifiez:
1. Le token dans `.env.local` ou GitHub secrets
2. Le `projectId` dans `chromatic.config.json`
3. Les permissions du token (doit avoir accès en écriture)

### Problème: Snapshots instables

```tsx
// Augmenter le délai de capture
parameters: {
  chromatic: { 
    delay: 500,
    pauseAnimationAtEnd: true 
  },
}
```
